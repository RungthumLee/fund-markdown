## ต้นทางไม่เก็บ "ชื่อเดิม"

`profiles` ของ SEC มี **ชื่อปัจจุบันชื่อเดียว** ต่อโครงการ — ตรวจครบทั้ง 4,892 แถวแล้ว
ไม่มีโครงการไหนที่มีชื่อหรือชื่อย่อมากกว่า 1 ค่า **ถ้ากองเปลี่ยนชื่อ ชื่อเก่าจะถูกเขียนทับหายไป**

ร่องรอยเดียวที่เหลืออยู่คือ **ชุดข้อมูล NAV รายวัน** เพราะ NAV แต่ละแถวมีฟิลด์
`fund_class_name` ซึ่งบันทึก**ชื่อชนิดหน่วยลงทุน ณ วันนั้น** — พอกองเปลี่ยนชื่อ
แถวเก่าก็ยังคงชื่อเดิมไว้ ส่วนแถวใหม่ใช้ชื่อใหม่

```
ASP-NCLR (M0068_2564)
  main       2021-08-02 .. 2024-10-31     ← ชื่อ class ตอนยังไม่มี multi-class
  ASP-POWER  2024-11-14 .. 2026-06-10     ← ตอนกองยังชื่อ "พลังงาน"
  main       2026-06-11 .. ปัจจุบัน        ← หลังเปลี่ยนเป็น "นิวเคลียร์"
```

**NAV ไม่ขาด** — ราคาต่อเนื่องกันข้ามรอยต่อ (ต่างกัน < 1%) สิ่งที่ขาดคือ *ป้ายชื่อ*

---

## ทำไมเรื่องนี้สำคัญ

ถ้าดึง series ด้วย `(proj_id, fund_class_name)` ตรง ๆ กองที่เปลี่ยนชื่อจะได้
ประวัติที่**ขาดเป็นช่วง ๆ** เช่น ASP-NCLR จะเหลือ 841 วันแทนที่จะเป็น 1,218 วัน
และช่องว่าง 588 วันตรงกลางจะถูกคำนวณเป็น "ผลตอบแทน 1 วัน" ก้อนใหญ่
ทำให้ **ความผันผวนและ correlation เพี้ยน**

---

## วิธีที่คลังนี้จัดการ

`scripts/nav_history.py` ต่อ series ให้อัตโนมัติ (`stitch_lineage`) โดยยอมต่อ
เมื่อผ่าน **3 เงื่อนไขพร้อมกัน**:

| เงื่อนไข | เหตุผล |
|---|---|
| ป้ายเก่ากับป้ายปัจจุบัน **ไม่เคยรายงานวันเดียวกันเลย** | ถ้ารายงานพร้อมกัน = คนละ class จริง ๆ ไม่ใช่ชื่อเก่า (เช่น `1AMSET50-RA` กับ `-RU` ราคาต่างกันไม่ถึง 1% แต่เป็นคนละชนิด **ห้ามต่อ**) |
| รอยต่อห่างกัน **ไม่เกิน 7 วัน** | เปลี่ยนชื่อแล้วรายงานต่อทันทีในวันทำการถัดไป |
| NAV ต่างกัน **ไม่เกิน 5%** ที่รอยต่อ | เปลี่ยนชื่อไม่ทำให้ราคาเปลี่ยน — ถ้าราคากระโดด แปลว่าไม่ใช่กองเดียวกัน |

ต่อได้ทั้งแบบ **ต่อท้อนหลัง** (ชื่อเก่า → ชื่อใหม่) และ **เติมช่องว่างตรงกลาง**
(กรณี ASP-NCLR ที่สลับป้ายไปแล้วกลับมา)

ผลปัจจุบัน: ต่อ series ให้ **116 กอง** — โน้ตของกองเหล่านั้นจะขึ้นกล่อง
"ชื่อเดิมที่พบในข้อมูล NAV" ไว้ให้เห็นชัดว่าอะไรถูกต่อเข้าด้วยกัน

> [!warning] สิ่งที่วิธีนี้**ไม่**ครอบคลุม
> - กองที่เปลี่ยนชื่อ**โดยที่ป้าย class ไม่เปลี่ยน** (เช่น class ชื่อ `main` ตลอด) —
>   จะไม่มีร่องรอยใดเหลืออยู่เลย **ตรวจไม่ได้จากข้อมูลชุดนี้**
> - การควบรวมกอง / เปลี่ยน `proj_id` — คนละโครงการ ไม่ถือว่าต่อเนื่อง
> - ตั้งแต่รอบนี้เป็นต้นไป `gen_changelog.py` จะบันทึกการเปลี่ยนชื่อที่เกิดขึ้น**ใหม่**เอง

## ช่องว่างอีกแบบ: ต้นทางหายจริง

คนละเรื่องกับการเปลี่ยนชื่อ — ชุดข้อมูล NAV ของ SEC **ขาดหายทั้งตลาด**
ช่วง **1–12 พฤศจิกายน 2024** (ยืนยันโดยเรียก API ตรง ๆ: ทั้งช่วงมีข้อมูลแค่ 21 แถว
เทียบกับช่วงข้างเคียงที่มีเป็นพัน) กระทบกองราว 1,500 กอง

และมีกองที่หายยาวเป็นรายกอง เช่น `B-EQUITY` ไม่มี NAV เลย 425 วัน
(2024-11 ถึง 2025-12) โดยไม่มีป้ายชื่ออื่นมารองรับ — อันนี้คือ**ข้อมูลขาดจริง**
ไม่ใช่การเปลี่ยนชื่อ

เพื่อไม่ให้ช่องว่างเหล่านี้กลายเป็นตัวเลขปลอม ทั้ง `nav_history.py` และ
`correlations.py` จะ**ข้ามคู่วันที่ห่างกันเกิน 7 วัน** ไม่นำมาคิดเป็นผลตอบแทนรายวัน
(ระดับราคายังจริง แต่ "ต่อวัน" ไม่จริง)
