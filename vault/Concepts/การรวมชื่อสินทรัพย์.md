# 🧩 การรวมชื่อสินทรัพย์

[[00-home|🏠 Home]] · [[../Indexes/by-holding|ดัชนีสินทรัพย์]] · [[Feeder Fund]] · [คู่มือเชิงเทคนิค](../../docs/guides/entity-normalization.md)

---

## ปัญหา

ข้อมูลพอร์ตจาก ก.ล.ต. มาจากระบบของ **แต่ละ บลจ. คนละระบบ**
สินทรัพย์ตัวเดียวกันจึงถูกสะกดต่างกันไปหมด

ตัวอย่างจริง — **SPDR Gold Shares** ปรากฏในช่อง `name` ถึง **29 แบบ**

```
B046RT1 US      ← SEDOL
US78463V1070    ← ISIN
GLDSP · GLD.US · GLDUS · GLD US   ← ticker ปนรหัสตลาด
2840 HK         ← ticker ตลาดฮ่องกง
SPDR SP · SSGA · WGC              ← ชื่อย่อผู้จัดการ
```

ช่อง `issuer` ก็ไม่ดีกว่า — `World Gold Trust Services` /
`World Gold Trust Service., LLC` / `STATE STREET BANK AND TRUST COMPANY`

> [!WARNING] ผลกระทบ
> ถ้าไม่รวมชื่อ **ตัวเลขการกระจุกตัวจะต่ำกว่าความจริง**
> เพราะฐานะเดียวถูกนับแยกเป็นหลายรายการ
> และคำถามพื้นฐานอย่าง "กองไทยกองไหนถือ Microsoft บ้าง" ตอบไม่ได้เลย

## วิธีรวม

### 1. ISIN คือความจริง

59% ของแถวมี ISIN ซึ่งระบุหลักทรัพย์ได้แม่นยำ 100%
ทุกแถวที่ ISIN ตรงกัน = สินทรัพย์เดียวกัน จบ

### 2. แถวที่ไม่มี ISIN → normalize ชื่อ

| ตัด | ตัวอย่าง |
|---|---|
| รหัสตลาดและส่วนต่อท้ายของ vendor | `MSFT US Equity` · `MSFTUW` · `MSFT.US` → `MSFT` |
| รูปแบบนิติบุคคล | `PCL` `PLC` `LLC` `INC` `บมจ.` `จำกัด (มหาชน)` |
| เครื่องหมายวรรคตอนและช่องว่างซ้ำ | |

จับคู่เฉพาะ**คีย์ที่ตรงกันเป๊ะ** ไม่ใช้ fuzzy matching
เพราะ fuzzy จะยุบ `CP ALL` เข้ากับ `CP AXTRA` ซึ่งเป็นคนละบริษัท

### 3. เลือกชื่อที่แสดงจาก "คุณภาพ" ไม่ใช่ "จำนวนครั้ง"

ถ้าโหวตตามความถี่ ทองคำจะได้ชื่อว่า `B046RT1 US` เพราะ SEDOL บังเอิญพบบ่อยที่สุด
ระบบจึงให้**คะแนน**แต่ละชื่อแทน

| ลักษณะ | คะแนน |
|---|---|
| หน้าตาเป็น ISIN | −50 |
| หน้าตาเป็น SEDOL | −40 |
| ticker สั้น ๆ ตัวพิมพ์ใหญ่ล้วน | −15 |
| มีหลายคำ | +25 |
| มีทั้งตัวพิมพ์ใหญ่และเล็ก (Mixed Case) | +15 |
| เป็นภาษาไทย | +20 |

และถ้า ISIN นั้นอยู่ใน[[../Indexes/master-funds|ทะเบียนกองทุนหลัก]]แล้ว
จะใช้ชื่อจากที่นั่นเลย เพราะ Yahoo/FT ให้ชื่อที่สะกดถูกต้องอยู่แล้ว

## สิ่งที่ไม่รวม (โดยตั้งใจ)

| กรณี | เหตุผล |
|---|---|
| **สัญญาอนุพันธ์ 19,424 แถว** | ช่อง `name` เป็นรหัสสัญญาภายใน (`CFX131239`) และ**ไม่มี issuer เลยสักแถว** — ไม่มีตัวตนให้รวม การสร้าง entity ต่อสัญญาจะได้ขยะ 18,000 รายการที่ไม่มีกองไหนถือซ้ำกัน |
| **เงินฝากกับหุ้นของธนาคารเดียวกัน** | ถือหุ้น KBANK กับฝากเงินไว้ที่ KBANK เป็นความเสี่ยงคนละแบบ จึงแยกเป็นคนละ entity |

> [!NOTE]
> เงินฝากใช้ช่อง `issuer` เป็นตัวตน เพราะช่อง `name` คือ**เลขที่บัญชี**
> (`SAVBBL2`, `0029239487 USD-FCD`) ซึ่งไม่ใช่ชื่อ

## ใช้ยังไง

โน้ตกองทุนหัวข้อ **7. พอร์ตการลงทุน** แสดงชื่อที่รวมแล้วพร้อมลิงก์ไปโน้ตสินทรัพย์
และยังคงแสดงชื่อดิบไว้ใต้บรรทัดเป็นตัวเล็ก เพื่อไม่ให้ข้อมูลต้นทางหายไป

โน้ตสินทรัพย์แสดง**กองไทยทุกกองที่ถือ** เรียงตามน้ำหนัก —
เป็นมุมกลับของโน้ตกองทุน

ค้นด้วย Dataview

````
```dataview
TABLE fund_count AS "กองที่ถือ", alias_count AS "ชื่อที่ต่างกัน"
FROM #multi-alias
SORT alias_count DESC
LIMIT 30
```
````
