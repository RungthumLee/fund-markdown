## อัลกอริทึม

### ชั้นที่ 1 — ISIN คือความจริง

ทุกแถวที่ ISIN ตรงกัน = entity เดียวกัน ไม่มีเงื่อนไขอื่น
`entity_id` = `isin:<ISIN>`

### ชั้นที่ 2 — แถวไม่มี ISIN → normalized key

```
"MSFT US Equity"  →  ตัด " Equity"  →  ตัดรหัสตลาด "US"   →  MSFT
"MSFTUW"          →  ตัดรหัสตลาดที่ติดท้าย "UW"            →  MSFT
"MSFT.US"         →  แทนที่จุดเป็นช่องว่าง แล้วตัด "US"     →  MSFT
"Microsoft Corp"  →  ตัดรูปแบบนิติบุคคล "Corp"            →  MICROSOFT
```

`entity_id` = `<kind>:<key>`

> [!IMPORTANT]
> จับคู่เฉพาะคีย์ที่**ตรงกันเป๊ะ** ไม่ใช้ fuzzy/edit-distance
> เพราะ fuzzy จะยุบ `CP ALL` เข้ากับ `CP AXTRA` และ `TISCO` เข้ากับ `TASCO`
> ซึ่งเป็นคนละบริษัท — ความผิดพลาดแบบนี้แก้ยากกว่าปล่อยให้แยกกัน

### ชั้นที่ 3 — พับกลุ่มที่ไม่มี ISIN เข้ากลุ่มที่มี

บลจ. A ส่ง `MSFT US` โดยไม่มี ISIN · บลจ. B ส่ง `Microsoft Corp` พร้อม
`US5949181045` → normalized key ตรงกัน จึงพับเข้าด้วยกัน (163 กลุ่ม)

### ชั้นที่ 4 — เลือกชื่อที่แสดง

**ไม่ใช้การโหวตตามความถี่** เพราะทองคำจะได้ชื่อว่า `B046RT1 US`
(SEDOL บังเอิญพบบ่อยที่สุด 13 ครั้ง) แต่ให้คะแนนแทน

| ลักษณะ | คะแนน |
|---|---|
| รูปแบบเป็น ISIN | −50 |
| รูปแบบเป็น SEDOL (7 ตัวไม่มีสระ) | −40 |
| ticker สั้น ≤5 ตัว พิมพ์ใหญ่ล้วน | −15 |
| มี `_` `/` หรือเป็น `[A-Z0-9]{2,8}` ล้วน | −10 |
| มีหลายคำ | +25 |
| ยาว ≥12 อักขระ | +15 |
| Mixed Case | +15 |
| เป็นภาษาไทย | +20 |

และถ้า ISIN อยู่ในทะเบียนกองทุนหลักแล้ว **ใช้ชื่อจากที่นั่นทันที**
(466 ISIN) เพราะ Yahoo/FT ให้ชื่อที่สะกดถูกต้องอยู่แล้ว

## สิ่งที่จงใจไม่รวม

### สัญญาอนุพันธ์ — 19,424 แถว

```json
{"name": "CFX131239", "issuer": "", "isin": null,
 "type": "สัญญาฟอร์เวิร์ด", "type_code": "402"}
```

`name` เป็นรหัสสัญญาภายในของ บลจ. และ **ไม่มี `issuer` เลยแม้แต่แถวเดียว**
ไม่มีตัวตนให้ resolve — การสร้าง entity ต่อสัญญาจะได้ขยะ ~18,000 รายการ
ที่ไม่มีกองไหนถือซ้ำกัน จึงนับแล้วข้าม และรายงานจำนวนไว้

> ถ้าต้องการวิเคราะห์ counterparty risk ของอนุพันธ์ ต้องหาแหล่งอื่น —
> ข้อมูลชุดนี้ไม่มี

### เงินฝากแยกจากหุ้นของธนาคารเดียวกัน

ถือหุ้น KBANK (`isin:TH0016010009`, 473 กอง) กับฝากเงินไว้ที่ KBANK
(`deposit:KASIKORNBANK`, 676 กอง) เป็นความเสี่ยงคนละแบบ
จึงอยู่คนละ entity โดยตั้งใจ

เงินฝากใช้ `issuer` เป็นตัวตน เพราะ `name` คือ**เลขบัญชี**
(`SAVBBL2`, `0029239487 USD-FCD`) — ถ้าเผลอเก็บ `name` เป็น alias
จะได้ alias ขยะ 638 รายการต่อธนาคารหนึ่งแห่ง
