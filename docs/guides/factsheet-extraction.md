# 📄 การแกะข้อมูลจาก Factsheet PDF

**ที่เกี่ยวข้อง:** [[pipeline|Pipeline]] · [[holdings-data|ข้อมูล Holdings]] · [[../api-reference/06-factsheet-urls|API: Factsheet URLs]] · [[../project/data-quality|Data Quality]]

---

## ทำไมต้องแกะ PDF ทั้งที่มี API แล้ว

API ให้ข้อมูลเชิงตัวเลขที่แม่นยำ แต่ **ไม่มี** ข้อมูลเหล่านี้เลย:

| ข้อมูล | API | Factsheet PDF |
|---|---|---|
| การจัดสรรตามกลุ่มอุตสาหกรรม (sector) | ❌ | ✅ |
| การจัดสรรตามประเทศ / ภูมิภาค | ❌ | ✅ |
| การจัดสรรตามอันดับความน่าเชื่อถือ (credit rating) | ❌ | ✅ |
| รายชื่อผู้จัดการกองทุน | ❌ | ✅ |
| กลุ่มกองทุนตาม AIMC | ❌ | ✅ |
| Holdings ของ **กองทุนหลัก** (feeder look-through) | ❌ | ✅ |
| ค่าธรรมเนียม / ผลตอบแทน / NAV / ความเสี่ยง | ✅ **แม่นกว่า** | ✅ |

หลักที่ยึด: **ตัวเลขการเงินใช้จาก API, มิติที่ API ไม่มีใช้จาก PDF**

## ขั้นตอน

```
fetch_factsheets.py   →  data/factsheets/<proj_id>.pdf
       ↓  PyMuPDF
parse_factsheets.py   →  vault/Factsheets/<ABBR>.md
       ↓  factsheet_sections.py
                      →  data/processed/factsheet_sections.json
       ↓
gen_vault.py          →  แทรกลงในโน้ตกองทุน หัวข้อ 7 และ 11
```

## วิธีแกะ (`scripts/factsheet_sections.py`)

Factsheet ของ ก.ล.ต. ใช้เทมเพลตเดียวกัน — แต่ละส่วนเป็น
**หัวข้อ** ตามด้วย **คู่ ชื่อ / ตัวเลข** สลับบรรทัดกัน

```
สัดส่วนประเภททรัพย์สินที่ลงทุน   ← หัวข้อ
ประเภททรัพย์สิน                  ← header (ข้าม)
% NAV                            ← header (ข้าม)
ตราสารทุน                        ← ชื่อ
80.77                            ← ค่า
พันธบัตร
11.18
```

### 1. จับหัวข้อแบบยืดหยุ่น

แต่ละ บลจ. เขียนหัวข้อไม่เหมือนกัน:
`ทรัพย์สินที่ลงทุน 5 อันดับแรก` · `ทรัพย์สินที่ลงทุนสูงสุด 5 อันดับแรก` ·
`ทรัพย์สินที่ลงทุน5 อันดับแรก`

จึงลบช่องว่างทั้งหมดก่อนเทียบ prefix

### 2. แยกกองทุนหลักออกจากกองไทย

Factsheet ของ [[../../vault/Concepts/Feeder Fund|feeder fund]] พิมพ์ตารางเดียวกัน **สองชุด** —
ของกองไทย และ `ของกองทุนหลัก` ถ้าเอามารวมกันน้ำหนักจะเกิน 100% มาก
โปรแกรมจึงเก็บแยกเป็น key ที่ลงท้ายด้วย `_master`

### 3. กู้ตารางที่ถูกกลืน

บาง บลจ. เขียนหัวข้อกองทุนหลักในรูปแบบที่จับไม่ได้ ทำให้สองตารางรวมกัน
สังเกตได้จาก **น้ำหนักที่เรียงลดหลั่นแล้วกระโดดกลับขึ้น** — จุดนั้นคือจุดเริ่มตารางใหม่
(`split_on_restart()`)

ตัวอย่างจริง — กองฟีดเดอร์กองหนึ่ง:

```
ของกองไทย : JPM US Growth I (acc) 101.06% · เงินฝากกรุงเทพ 2.99% · ... 0.02%
                                                          ↑ กระโดดกลับขึ้น
ของกองหลัก: Alphabet 9.7% · Nvidia 9.1% · Apple 5.5% · ...
```

### 4. รายชื่อผู้จัดการกองทุน

บังคับให้ขึ้นต้นด้วยคำนำหน้าไทย (`นาย` `นาง` `น.ส.` `ดร.`)
ถ้าไม่บังคับ จะไปดูดชื่อกองทุนและ ticker ที่พิมพ์อยู่ใต้รายชื่อมาด้วย

## สิ่งที่แกะได้ (ค่าที่วัดจากการรันจริง)

| ส่วน | จำนวนกองที่แกะได้ |

| `statistics` สถิติตามที่พิมพ์ | ~1,300 |

| `sectors` กลุ่มอุตสาหกรรม | ~400 |

> กองที่แกะไม่ได้ครบทุกส่วนไม่ใช่ข้อผิดพลาด — factsheet ของกองตราสารหนี้
> ไม่มีตารางกลุ่มอุตสาหกรรม และกองในประเทศไม่มีตารางประเทศอยู่แล้ว

## ข้อจำกัด

> [!WARNING]
> - การแกะอาศัย **ลำดับข้อความที่ PyMuPDF อ่านได้** ถ้า บลจ. เปลี่ยน layout อาจคลาดเคลื่อน
> - ตัวเลขที่ได้เป็น **best-effort** — ทุกโน้ตมีคำเตือนกำกับและลิงก์กลับไปโน้ตกองทุน
>   ซึ่งใช้ตัวเลขจาก API
> - **ไม่ได้แกะ** ค่าธรรมเนียม ผลตอบแทน NAV ระดับความเสี่ยงจาก PDF โดยตั้งใจ
>   เพราะ API ให้ข้อมูลเดียวกันแบบมีโครงสร้างและแม่นกว่า
>   (เคยลองแล้ว regex จับ "ระดับความเสี่ยง" ไปโดนแถบมาตราส่วน 1–8 แทนค่าจริง)

## รันเอง

```bash
python scripts/fetch_factsheets.py          # โหลด PDF (~30 วินาที)
python scripts/parse_factsheets.py --force  # แกะใหม่ทั้งหมด (~2 นาที)
python scripts/gen_vault.py                 # แทรกลงโน้ตกองทุน
```

ทดสอบการแกะกองเดียว:

```python
import sys, fitz; sys.path.insert(0, "scripts")
from factsheet_sections import extract

with fitz.open("data/factsheets/M0009_2543.pdf") as doc:
    text = "\n".join(p.get_text("text") for p in doc)
print(extract(text))
```
