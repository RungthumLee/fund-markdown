## 🟢 OUT-001 — RMF ตรวจจับด้วยชื่อกองทุน — **แก้แล้ว (2026-08-28)**

**สถานะ:** ✅ เปลี่ยนสัญญาณจาก "ชื่อย่อ" เป็น "ชื่อจดทะเบียน"

API ไม่มี flag แยกสำหรับ RMF — ยืนยันจากการนับทุกแถวใน `profiles.jsonl`:
`fund_class_tax_incentive_type` มีแค่ 2 ค่าคือ SSF (398) และ Thai ESG (44) เท่านั้น
**ไม่มีค่า RMF เลย**

**สิ่งที่แก้:** `scripts/tagging.py` → `_is_rmf()` ใช้ **ชื่อตามกฎหมาย**
`"เพื่อการเลี้ยงชีพ"` (ซึ่งกอง RMF ต้องใช้ในชื่อจดทะเบียน) + ชื่ออังกฤษ
`RMF`/`retirement` แทนการดูตัวอักษร `RMF` ในชื่อย่อ

**ผลที่วัดได้:** ชื่อจดทะเบียนครอบคลุม 379 โครงการ เป็น **superset ของ 341 โครงการ**
ที่วิธีเดิมหาเจอ (ชื่อย่อไม่เจอกองที่ชื่อจดทะเบียนเจอ = **0**) และเพิ่มกอง RMF จริง
ที่ชื่อย่อไม่มีคำว่า RMF เช่น `M-VALUE` (MFC Retirement Value Fund) ·
`SCBRMS&P500` · `SCB2576` — ในขอบเขต 2,121 กอง: tag `#tax/rmf` **341 → 377 กอง**

**ที่ยังเหลือ:** ยังเป็นการอ่านชื่อ ไม่ใช่ flag จากต้นทาง — ถ้า SEC เพิ่ม
`fund_class_tax_incentive_type = RMF` เมื่อไหร่ ควรย้ายไปใช้ field นั้นแทน

## 🟡 OUT-002 — เพดาน rate limit — **วัดแล้ว: เป็น quota ต่อเนื่อง ไม่ใช่ burst**

**สถานะ:** ✅ วัดจริงแล้ว 2026-08-28 · คงค่าอนุรักษ์นิยม `rate_delay=0.12` (ยิงเรียงต่อกัน)

### รอบที่ 1 — burst probe (`scripts/probe_history.py`) : ไม่เจอเพดาน

| รูปแบบยิง | อัตราที่ทำได้ | 429 |
|---|---|---|
| เรียงต่อกัน ไม่หน่วง (40 calls) | 12.1 req/s | 0 |
| ขนาน 2 threads (40 calls) | 25.3 req/s | 0 |
| ขนาน 4 threads (40 calls) | 43.5 req/s | 0 |
| ขนาน 8 threads (40 calls) | 73.0 req/s | 0 |

### รอบที่ 2 — งานจริง (backfill NAV 5 ปี) : **เจอ 429**

- ขนาน **4 workers** → เจอ 429 ภายใน **~3 นาที** และเจอต่อเนื่อง (29 ครั้ง)
  บาง slice ยิงจนครบ 5 retry แล้วตาย throughput ตกจาก 420 KB/s เหลือ ~15 KB/s
- **เรียงต่อกัน (workers=1, delay 0.12)** → **429 = 0** · ~120 KB/s สม่ำเสมอ

> [!IMPORTANT] บทเรียน: **burst test โกหกได้**
> ยิง 40 call รัว ๆ ไม่เจออะไรเลยแม้ที่ 73 req/s แต่ตัว limiter จริงเป็น
> **quota แบบต่อเนื่อง** ที่โผล่มาเมื่อยิงเป็นหมื่น call ติดกัน — การทดสอบสั้น ๆ
> จึงพิสูจน์ได้แค่ว่า "ไม่มี burst limit" ไม่ได้แปลว่า "ไม่มีเพดาน"
> ตระกูลเดียวกับ [[issues|ISS-009]]: ตัวเลขที่ดูน่าเชื่อ อันตรายกว่าไม่มีตัวเลข

**ข้อสรุปที่ใช้จริง:** ดึงข้อมูลก้อนใหญ่ให้ยิง**เรียงต่อกัน**ด้วย delay 0.12
(`scripts/harvest.py` default `--workers=1`) · โค้ดขนานมีไว้แต่ไม่แนะนำ ·
ยังไม่รู้ตัวเลข quota ที่แน่นอน (SEC ไม่ประกาศ) — ดู [[issues|ISS-005]] ·
ผลดิบที่ `data/processed/history_probe.json`
