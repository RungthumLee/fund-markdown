## 🟢 ISS-001 — Developer portal ตอบ 403 ต่อ automated request

**พบเมื่อ:** ขั้นตอนสำรวจ API
**อาการ:** `GET https://secopendata.sec.or.th/sec-open-apis?...` คืน `403 Block Response`
ทั้งจาก WebFetch และ `curl` (แม้ตั้ง User-Agent เป็นเบราว์เซอร์)
พร้อม HTML block page — เป็น WAF/bot protection ฝั่ง portal

**ผลกระทบ:** ดึงสเปกจากหน้าเว็บโดยตรงไม่ได้

**วิธีแก้:** ใช้ machine-readable mirror ของ catalog เดียวกัน
`github.com/Sitthinut/sec-open-data-api-spec` → `spec/categories/fund.json` (244 KB)
ครบทั้ง 21 endpoint พร้อม parameter, data dictionary และ example
เก็บสำเนาไว้ที่ `_spec/fund.json` เพื่อ reproducibility

**หมายเหตุ:** ตัว **API เอง** (`api.sec.or.th`) ไม่ได้ถูกบล็อก — เรียกได้ปกติด้วย subscription key

## 🟢 ISS-002 — `UnicodeEncodeError: surrogates not allowed` เมื่อ pipe ผ่าน shell

**อาการ:** `curl ... | python -c "..."` พังที่ข้อความภาษาไทย
```
UnicodeEncodeError: 'utf-8' codec can't encode character '\udc9a'
```
**สาเหตุ:** Git Bash บน Windows ส่ง stdout เป็น cp874/mbcs ทำให้ไทยกลายเป็น surrogate

**วิธีแก้:** ไม่ pipe ข้อความไทยผ่าน shell — ใช้ `requests` ใน Python
แล้วเขียนไฟล์ด้วย `encoding="utf-8"` โดยตรง ทุกสคริปต์ในโปรเจกต์นี้ทำแบบนี้ทั้งหมด

## 🟢 ISS-011 — validator รายงานลิงก์เสีย 25 รายการที่ไม่ได้เสียจริง

**อาการ:** เป้าหมายลิงก์ลงท้ายด้วย `\` เช่น `` `T. Rowe Price US Blue Chip Eq I\` ``

**สาเหตุ:** สองชั้น
1. ในตาราง markdown ต้อง escape `|` เป็น `\|` — regex ของ validator
   ดูดเครื่องหมาย `\` เข้าไปในชื่อเป้าหมาย
2. fallback ใช้ `Path(target).stem` ซึ่งตัดชื่อที่มีจุดทิ้ง —
   `T. Rowe Price US Blue Chip Eq I` เหลือแค่ `T`

**วิธีแก้:** ปรับ regex ให้ยอมรับและตัด `\` ท้ายชื่อ และใช้ `Path().name`
เฉพาะเมื่อเป้าหมายมี `/` จริง ๆ

**บทเรียน:** เครื่องมือตรวจสอบเองก็มี bug ได้ — ก่อนไล่แก้ "ลิงก์เสีย"
ควรเปิดไฟล์จริงดูก่อนว่าเสียจริงไหม

**ผลหลังแก้:** กองที่ไม่มีข้อมูล 111 → 101 (ได้คืน 10 กองโดยไม่ต้องค้นเว็บเลย)

## 🟢 ISS-021 — เทียบ "ค่าที่เก็บจริง" กับ "เพดาน" แล้วสรุปว่าข้อมูลผิด

**พบเมื่อ:** ตรวจซ้ำโค้ดของ `fees.py` ที่เพิ่งเขียนเอง

**อาการที่รายงานไว้ตอนแรก (ผิด):** "308 ชนิดใน 216 กองรายงาน Total Fee
ต่ำกว่า Management Fee ซึ่งเป็นไปไม่ได้"

**สาเหตุจริง:** `_value()` อ่านค่าโดยเอา `actual` ก่อน ถ้าไม่มีจึงใช้ `rate`


`is_suspect()` เทียบ actual กับ actual เท่านั้น

**ผลหลังแก้:** คลาสที่ผิดจริง **308 → 46** (32 กอง)

**บทเรียน:** fallback ที่ดูไม่มีพิษภัย (`actual or rate`) สร้างการเทียบข้ามหน่วย
ที่มองไม่เห็น — และมันไปทำให้ตัวเลขผลกระทบของ ISS-020 สูงเกินจริงสองเท่าด้วย

สัดส่วนจะตกและ **exit 1**

| โฟลเดอร์ | หัวข้อ | วัดได้จริง | เกณฑ์ |

แต่บล็อกหายทั้งบล็อกจะจับได้

**บทเรียน:** ความล้มเหลวที่ไม่ส่งเสียงต้องแก้ด้วยการ**นับ** ไม่ใช่ด้วยความระมัดระวัง
เช่นเดียวกับ [[issues|ISS-026]] ที่ต้องนับไฟล์ที่เขียนเทียบกับไฟล์ที่มีจริง

## 🔴 ISS-035 — ตัวตนหลักทรัพย์ไทยถูกตั้งชื่อเป็นบริษัทต่างประเทศที่ ticker ชนกัน

**พบเมื่อ:** สร้าง `scripts/validate_semantics.py` (semantic validator ตัวใหม่)
แล้วมันจับได้ทันทีในรอบแรก

**อาการ:** หลักทรัพย์ ISIN `TH0128B10Z09` ซึ่งคือ **Minor International (MINT)**
ถูก resolve เป็น entity ชื่อ **"Mapletree Industrial Trust"** (REIT สิงคโปร์)
โน้ตกองทุน **377 ฉบับ** ที่ถือ MINT จึงลิงก์ไปบริษัทผิด

**สาเหตุ:** `MINT` เป็น ticker ที่ชนกันข้ามตลาด — ไทยคือ Minor International
แต่ vendor อื่น (ผ่าน Yahoo/master-fund enrichment) ใช้ `MINT` กับ Mapletree
`name_quality()` ให้คะแนนชื่อจากต่างตลาดสูงกว่า จึงเขียนทับชื่อจริงบน ISIN ไทย
ตระกูลเดียวกับ [[issues|ISS-022]] / [[issues|ISS-023]] (symbol matching ข้ามตลาด)

**ขอบเขต:** จาก validator รอบแรก — entity ที่ชื่อผิด **3 ตัว** ครอบคลุม 379 การอ้างอิง
- `Mapletree Industrial Trust` ← ควรเป็น Minor International (377 กอง)
- `THBEV SP Equity` ← ticker Bloomberg แทนชื่อจริง Thai Beverage (1 กอง)
- `Invesco Solar ETF` ← ผูกผิดกับ Tanachira Retail (1 กอง)

**วิธีแก้ (ทำแล้ว):** ที่ขั้นเลือกชื่อใน `normalize_entities.py` — สำหรับหลักทรัพย์
`kind = equity/reit` ที่มี **ISIN ไทย** ให้ยึด **issuer ที่ถูกยื่นบ่อยที่สุด**
เป็นชื่อ (ผู้ออกที่จดทะเบียนคือตัวตนจริงของหุ้นไทย) ถ้าชื่อที่เลือกไว้ token
ไม่ตรง issuer หลักเลย ให้สร้างใหม่จากผู้สมัครที่ตรง issuer เท่านั้น
(`name_source = "issuer-th"`) — จำกัดเฉพาะ equity/reit เพื่อไม่แตะเคสกองถือกอง
(issuer เป็น บลจ.)

**ผลหลังแก้:** entity ที่แก้ชื่อ **3 ตัว** (Minor International, Thai Beverage,
Tanachira Retail) · **S1 = 3 → 0** · โน้ตกองทุน 377 ฉบับลิงก์ไป Minor ถูกต้อง
ตั้ง `S1_BUDGET = 0` — collision ใหม่ในอนาคตจะทำให้ run fail ทันที

**สถานะ:** 🟢 แก้แล้ว (validator เขียว) — ต้นเหตุคือ symbol fold ข้ามตลาด (ISS-022)
ที่ดูด "MINT" สิงคโปร์เข้ากลุ่ม ISIN ไทย ชื่อ mixed-case จึงชนะ `best_name`

**บทเรียน:** validator เดิม (`validate_vault.py`) ตรวจ**โครงสร้าง** (ลิงก์/ไฟล์/ชื่อ)
ทั้งหมดผ่านหมด แต่มองไม่เห็นว่าตัวตน**ผิดความหมาย** — ต้องมีตัวตรวจที่ถาม
"ค่ามันสมเหตุสมผลไหม" แยกต่างหาก ดู [[semantic-report|Semantic Report]]

## 🟢 ISS-035b — ISIN ไทยหนึ่งตัวถูกใช้กับสองหลักทรัพย์ (แยกออกจาก ISS-035)

**พบเมื่อ:** หลังแก้ ISS-035 validator ยังเหลือ S1 = 1 ที่กลับด้าน

**อาการ:** 5 กองอสังหา (KKP PROP, K-PROPI, …) ถือ **Mapletree Industrial Trust
จริง** (REIT สิงคโปร์) แต่ บลจ. กรอกโดยเว้นช่อง ISIN ว่างและใส่ชื่อ `MINT`

**ต่างจาก ISS-035:** คราวนั้น**ชื่อ entity ผิด** (แก้ที่เราได้) · คราวนี้**ชื่อถูก**

ตัวตัดสิน ถ้าชื่อตรง issuer หลักแล้วแต่มีแถวส่วนน้อย issuer ต่าง → เข้า S8

**สถานะ:** 🟢 S8 เตือนไว้ 5 กอง — เป็นข้อมูลต้นทาง ไม่นับเป็นบั๊ก pipeline
